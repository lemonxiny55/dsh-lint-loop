The first live attempt exposed two integration defects before this successful
run: the fs intent waterfall could be short-circuited by DSH's earlier policy,
and an optional `error: undefined` field made the repair receipt fail DSH's
lossless-JSON validation even though the fixer had run. v0.5.0 now tracks
successful `edit`/`write` calls through `tools/execute`, keys state by stable
session ID, and omits absent optional receipt fields. New tests cover both
boundaries. DSH's configured model returned intermittent HTTP 429 rate-limit
errors during the smoke; automatic retries recovered and the full workflow
completed successfully.

## Release scope

- `lint_repair { scope: "turn" }` considers only files successfully edited or
  written by the Agent in that turn. It groups work by linter and package/crate,
  uses existing fixers, verifies each result, and stops after at most two rounds.
- Historical findings remain in the receipt as ignored; package/crate fixers
  fail closed when their wider scope contains unrelated findings. File-local
  fixers roll back when verification fails or introduces a finding.
- `lint_status` is the in-session status surface. A slash command was not added
  because the inspected DSH plugin API does not expose a reliable
  slash-command registration seam.
- Stylelint was deferred to keep the release focused on regression-aware
  repair and bounded validation.
